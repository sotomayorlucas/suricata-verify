# One lost TCP segment ends dnp3 parsing for the rest of the flow

Two long-lived dnp3 connections, 20 marked requests each (10.128.0.0 and 10.128.0.1 ->
10.0.0.2:20000). Every frame travels in two TCP segments. The second half of request 6 on
10.128.0.0 is missing from the capture (a capture drop): a TCP gap inside a frame.

Current behaviour: the parser does not accept gaps, so the app-layer is disabled for that flow.
10.128.0.0 logs only the 5 requests before the gap; 10.128.0.1 logs all 20.

The pcap was generated by input.py (Python, see its docstring).
